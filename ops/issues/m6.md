### Describe the bug
In an established session, an encrypted frame shorter than the 4-byte sequence number (e.g. 2 bytes) is silently ignored, and the session carries on. An encrypted frame that fails authentication (bad GCM tag) terminates the session, so short frames are handled inconsistently.

Cause: `MobileWalletAdapterSessionCommon.decryptSessionPayload` calls `ByteBuffer.wrap(payload, 0, SEQ_NUM_LENGTH_BYTES).getInt()` first. For a short payload `ByteBuffer.wrap` throws `IndexOutOfBoundsException`, which is not a `SessionMessageException`. So `receiverMessageReceived` doesn't call `onSessionError()`, and the transport drops the exception.

### Expected vs actual behavior
Expected: the session is terminated, as for a frame with a bad tag.
Actual: the frame is ignored; the next valid request on the same session is answered normally.

### Suggested fix
At the top of `decryptSessionPayload`, reject payloads shorter than `SEQ_NUM_LENGTH_BYTES + AES_IV_LENGTH_BYTES + AES_TAG_LENGTH_BYTES` with a `SessionMessageException`.

Full patch for this and the three related issues: https://github.com/let-the-dreamers-rise/mwa-gauntlet/blob/main/patches/public-fixes.patch. With it, the full `common`, `walletlib` and `clientlib` unit suites still pass.
