### Describe the bug
Some malformed requests get no response at all, so the dapp waits until its own timeout:

- `sign_messages` without `addresses`
- `sign_messages` with `"addresses": [null]`
- `authorize` with a `sign_in_payload` that fails to parse (e.g. `"nonce":"!"`, `"issuedAt":"not-a-date"`)

Cause: `MobileWalletAdapterServer.dispatchRpc` catches only `IOException`. The `IllegalArgumentException` / `JSONException` thrown while parsing these params escapes `receiverMessageReceived`. Java-WebSocket's `onMessage` handling logs it and drops it, so no response is sent. The session itself survives.

### Expected vs actual behavior
Expected: an error response (e.g. `-32602` invalid params) for each.
Actual: nothing; `replies` stays empty for the 3 s the test waits. A following valid `sign_transactions` on the same session still works.

### Suggested fix
In `dispatchRpc`, also catch `RuntimeException` and answer `ERROR_INVALID_PARAMS` ("params are not valid"), logging the exception. Tests `m4a`/`m4b`/`m4c` check that each request gets exactly one error reply and that the session stays usable afterwards.

Full patch for this and the three related issues: https://github.com/let-the-dreamers-rise/mwa-gauntlet/blob/main/patches/public-fixes.patch. With it, the full `common`, `walletlib` and `clientlib` unit suites still pass.
