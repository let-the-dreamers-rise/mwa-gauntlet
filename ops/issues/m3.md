### Describe the bug
When a dapp calls `get_capabilities` with non-empty params, walletlib sends **two** JSON-RPC responses with the same id. The first is the error `-32602 "params expected to be empty"` and the second is the full capabilities result. JSON-RPC 2.0 allows exactly one response per request, so a dapp's client can resolve the request with either one, depending on how it matches ids.

Cause: `MobileWalletAdapterServer.handleGetCapabilities` calls `handleRpcError(...)` for non-empty params but has no `return` afterwards, so it goes on to build and send the result.

### Expected vs actual behavior
Expected: one response, the `-32602` error.
Actual: two responses for id 5:
```
{"jsonrpc":"2.0","error":{"code":-32602,"message":"params expected to be empty"},"id":5}
{"jsonrpc":"2.0","result":{...capabilities...},"id":5}
```

### Suggested fix
Add `return;` after the `handleRpcError` call in `handleGetCapabilities`.

Full patch for this and the three related issues: https://github.com/let-the-dreamers-rise/mwa-gauntlet/blob/main/patches/public-fixes.patch. With it, the full `common`, `walletlib` and `clientlib` unit suites still pass.
